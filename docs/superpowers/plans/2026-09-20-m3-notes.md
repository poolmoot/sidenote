## Behaviour
1. **List:** notes sorted by `updatedAt`, newest first. Title is the first non-empty line (trimmed, "New note" when empty); one more line as preview. `+` creates an empty note, opens the editor and focuses it.
2. **Editor:** plain `TextEditor` bound to the note's text. Every change bumps `updatedAt` and asks the store to save (debounced by `JSONFileStore`). Leaving the editor (back chevron) or folding the notch flushes.
3. **Checkboxes:** a line matching `- [ ] text` or `- [x] text` renders as a tickable row under the editor's rendered preview. Toggling rewrites only that line's marker, keeps the rest of the text byte-identical, and saves. `ChecklistLine` parsing is pure and fully tested (leading spaces preserved, `[X]` uppercase accepted, `-[ ]` without space is plain text, empty text after the marker allowed).
4. **Delete:** ✕ on a list row deletes; ⌘Z restores it (single-level undo held in the store, cleared when the widget closes). The editing lock (`WidgetContext.setEditing`) is engaged while the editor has focus, so the notch doesn't fold while typing.
5. **Links:** URLs in the rendered preview are clickable (`AttributedString` autodetection); clicking opens the default browser.
6. **Errors:** a note whose text fails to save logs through `AppIdentity.logger("notes")`; the in-memory note is kept (spec §6).
7. **No polling.** No timers; autosave uses the existing debounce.

## Tests (first)
- `ChecklistLine`: unchecked/checked/uppercase/leading-space/no-space/empty-text/plain parsing; toggle rewrites only the marker and preserves the rest of the document.
- `NotesStore` (in a temp directory, through `JSONFileStore`): create returns a focused empty note; update bumps `updatedAt` and reorders; delete + undo restores position; toggleCheckbox flips one line only; notes survive a reload; title/preview derivation, including an empty note and a note whose first lines are blank.
